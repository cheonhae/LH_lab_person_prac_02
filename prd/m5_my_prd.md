# PRD — 홍보 예산 집행 검증기

| 항목 | 내용 |
|---|---|
| 주 사용자 | 주거복지부 예산담당 (보조: 임대공급팀 홍보 예산 정리 담당자) |
| 결과물 형태 | HTML 파일 하나로 된 웹앱 `tools/m5_budget_check.html`, GitHub Pages 배포 |
| 입력 데이터 | 가상 표본 CSV 파일만 |
| 작성 | 2026. 11. 24.(화) · PRD 인터뷰(코어) 결과 |

## 1. 프로젝트 개요

- 해결하려는 문제: 홍보 예산 집행 내역의 항목별 금액 합과 보고서 총액이 맞지 않는데, 손으로 대조하다 보니 결재·감사 전에 놓친다.
- 배경: 최근 감사·결재에서 합계 오류를 지적받았고, 담당자 교체·인수인계로 기존 방식에 대한 불안이 커졌다.
- 기대 변화: 눈으로 대조하다 사후에 발견 → 결재 전에 자동으로 합계를 검산해 어긋난 항목과 차이 금액을 바로 확인.

## 2. 사용자 분석

- 주 사용자: 주거복지부 예산담당. 임대공급팀이 올린 홍보 예산 집행 보고서를 결재 전에 검토한다.
- 보조 사용자: 임대공급팀 홍보 예산 정리 담당자.
- 사용 맥락: 임대공급팀 보고서를 받은 뒤, 결재·감사로 넘기기 전 검토 단계.
- 현재 해결 방식: 받은 엑셀 표에 SUM을 걸어 총액과 비교한다.
- 한계: 수식 범위에서 행이 빠져도 알아채기 어렵다. 문자로 입력된 숫자는 합계에서 조용히 빠진다. 총액이 다르다는 것만 보여 어긋난 항목을 다시 찾아야 한다. 표마다 수식을 새로 걸어야 한다.

## 3. 기능 요구사항

### 3.1 핵심 기능 (우선순위 순, 3개 모두 이번 범위)

| 순위 | 기능 | 설명 |
|---|---|---|
| 1 | 이상 행 걸러내고 정상 기준 집계 | 문자 숫자·빈칸·중복 행을 찾아 경고하고, 화면에 고정된 정상 기준에 맞는 행만 다시 합산한다. |
| 2 | 어긋난 곳 표시 | 보고서의 소계·총액과 다시 계산한 값을 비교해 어느 구분·총액이 얼마나 다른지 차이 금액을 보여 준다. |
| 3 | 집계 근거 파일 생성 | 집계 결과 / 제외 사유와 원본 값 / 실행 로그를 파일 세 개로 내려받는다. 빈칸 행 등 제외 행의 사유는 '제외 사유와 원본 값' 파일에 기록한다. |

- 다음 버전: CSV 붙여 넣기·직접 입력.
- 차별점: SUM은 "총액이 다르다"만 알려 주지만, 이 검증기는 어떤 행을 왜 뺐고 어디가 얼마나 어긋났는지를 근거 파일로 남겨 결재·감사 때 설명 자료로 쓸 수 있다.

### 3.2 입력 CSV 형식

- 열: `구분`, `항목명`, `집행금액`. 행 번호는 머리행을 빼고 1부터 센다.
- `항목명`이 `소계`인 행은 그 `구분`의 보고서 소계, `합계`인 행은 보고서 총액으로 읽고 집계 대상에서 뺀다.
- 쉼표가 든 금액(`1,000,000`)은 쉼표를 빼고 숫자로 읽는다.

### 3.3 정상 기준 (화면에 고정, 사용자가 바꾸지 않음)

| 기준 | 판정 | 처리 |
|---|---|---|
| 빈칸 | `구분`·`항목명`·`집행금액` 중 하나라도 비어 있음 | 제외, 사유를 파일에 기록 |
| 문자 숫자 | `집행금액`에 숫자·쉼표 외 글자가 있음(예: `1,000원`, `백만`) | 제외, 사유를 파일에 기록. 고쳐서 포함할지는 담당 검토 |
| 중복 행 | 모든 열 값이 앞 행과 같음 | 처음 나온 행만 포함, 두 번째부터 제외하고 "중복(n행과 같음)"을 기록 |

### 3.4 화면

| 화면 | 하는 일 |
|---|---|
| ① 파일 선택 | CSV 파일을 고르고, 화면에 고정된 정상 기준 3가지를 보여 준다. "가상 표본만 넣으세요" 안내를 띄운다. |
| ② 검사 결과 | 전체·포함·제외 행 수, 제외 행 목록(행 번호·사유·원본 값), 구분별 재집계 소계와 보고서 소계의 차이, 재집계 총액과 보고서 총액의 차이를 보여 준다. 결과 위에 "담당 검토 후 확정"을 표시한다. |
| ③ 근거 파일·백업 | 근거 파일 세 개(집계 결과·제외 사유와 원본 값·실행 로그)와 JSON 백업 파일을 내려받는다. JSON 백업 파일을 골라 가져오면 그 검사 결과를 ② 화면에 다시 보여 준다. |

## 4. 비기능 요구사항

- 결과물: `tools/m5_budget_check.html` 한 파일. 브라우저에서 열어 쓰고 GitHub Pages 주소로 배포한다.
- 없는 것: 서버·로그인·설치·외부 라이브러리·외부 전송.
- 입력: CSV 파일 선택. 가상 표본만 넣는다. (백업 복원용으로 JSON 백업 파일 선택)
- 저장: 브라우저 안 localStorage 키 하나 `m5_budget_check`에 마지막 검사 결과를 둔다. JSON 백업 파일로 내보내고 가져올 수 있다. 가져오면 저장된 결과를 덮어쓴다. 형식이 맞지 않는 파일은 가져오지 않고 안내를 띄운다.
- 데이터 민감도: 가상 표본으로만 시험한다. 데이터를 외부로 보내지 않는다.
- 제약: 1인 개발, 45분. 배포 주소는 누구나 열 수 있다. 정상 기준은 화면에 고정한다. 판정은 확정하지 않고 "담당 검토 후 확정"으로 표시한다.

## 5. 성공 지표

- 성공 모습: CSV 하나를 넣으면 총액 일치 여부, 어긋난 항목과 차이 금액, 제외 행과 사유를 확인할 수 있다.
- 성공 시나리오 (화면에서 판정)
  - S1: 오류 없는 정상 표본 CSV를 넣으면 → "합계 일치", 경고 0건, 제외 0행이 보인다.
  - S2: 한 구분의 항목 금액 하나를 바꿔 보고서 소계·총액과 합이 다른 표본 CSV를 넣으면 → "합계 불일치"와 함께 어긋난 구분과 차이 금액(예: −500,000원)이 보인다.
  - S3: 빈칸·문자 숫자·중복 행을 하나씩 심은 표본 CSV를 넣으면 → 제외 3행이 행 번호·사유·원본 값과 함께 보이고, 정상 기준 재집계 총액과 근거 파일 세 개 내려받기 버튼이 보인다.
- 핵심 지표: S1~S3 표본 시험에서 심어 둔 오류 놓침 0건, 정상 행을 오류로 잘못 잡음 0건.
- 참고 지표(표본으로 판정하지 않음): SUM 대조보다 줄어든 검토 시간.
