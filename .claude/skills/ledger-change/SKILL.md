# 대장 변경 영향 반영 절차

## 1. 언제 쓰나
- 정정 메모(`inputs/m*/*정정메모*.md`)가 대장 항목의 값(날짜·건수 등)을 바꿀 때 쓴다.
- 대장 값을 쓰는 문서(공문·보고·신구대비표 초안, 회의록)를 새 값에 맞출 때 쓴다.
- 전사본으로 회의록을 새로 쓰거나 CSV를 집계하는 일은 이 스킬의 범위가 아니다(`admin-verify` 참고).

## 2. 입력
- 정정 메모: 바뀌는 항목, 변경 전 → 후 값, 사유, 게시·작성 일자
- 기준 파일: `CLAUDE.md` 3절(정합 규칙), `ledger/ledger.csv`
- 대상 문서: 해당 모듈 `inputs/m{n}/README.md`가 지정한 초안과 회의록 절

## 3. 절차
**1단계 — 변경 항목 확정 (고치지 않음)**
1. 정정 메모에서 바뀌는 값과 **바뀌지 않는 관련 값**(예: 마감만 연장, 시작일은 그대로)을 나눈다.
2. `ledger/ledger.csv`에서 해당 항목ID를 찾는다. 대장에 없는 항목이면 새 항목ID 후보를 제안하고 `{확인 필요: 대장 신규 항목}`으로 표시한다. 임의로 추가하지 않는다.

**2단계 — 영향 목록 작성 후 멈춤**
1. 대상 문서 전부에서 변경 전 값을 찾는다. 표기 차이를 모두 검색한다(`2026. 11. 13.(금)`, `11. 13.(금)`, `11. 13.`, `2026-11-13`).
2. 찾은 곳마다 문맥을 읽고 이 대장 항목을 가리키는지 판단한다. 같은 날짜라도 다른 항목이면 제외한다.
3. `outputs/m{n}/impact_list.md`를 아래 형식으로 만든다.
   - 1절 바뀌는 대장 항목: `| 항목ID | 항목 | 변경 전 | 변경 후 | 변경하지 않는 관련 항목 |`
   - 2절 영향 목록: `| 대장 항목 | 변경 전 → 후 | 영향 문서 | 위치(줄 번호 + 원문 인용) | 승인 |`. 승인 칸은 ☐로 비워 둔다.
   - 합계: 문서 수, 위치 수
   - 3절 승인 전에 확인할 점: 날짜만 바꾸면 어긋나는 곳(시행일, 판 표기 v2/v3, 요일), 회의 당시 기록인 절, 신구대비표 현행 칸, 이미 만든 `doc_*.md` 수정본
4. **여기서 멈추고** 사용자에게 목록을 보여 준 뒤 승인을 받는다. 승인 전에는 대장과 문서를 고치지 않는다.

**3단계 — 승인한 위치를 한꺼번에 고침**
1. `ledger/ledger.csv`: 값 칸을 바꾸고, 기준일을 정정 게시일로, 출처 칸에 정정 메모 경로를 더하고, 비고 칸에 "변경 전 값에서 연장/변경, 사유"를 적는다.
2. 초안 문서: `inputs/`는 그대로 두고 `outputs/m{n}/doc_{원본 ID}.md`로 새로 만든다. 이미 있으면 그 파일에서 고친다.
3. 회의록: 지정한 절만 그 자리에서 고친다.
4. 승인 칸이 ☑인 위치의 값만 바꾼다. 나머지 문장은 한 글자도 바꾸지 않는다. 3절의 결정 사항(판 표기, 시행일 등)은 사용자가 정한 대로만 반영한다.
5. 고친 뒤 `diff`로 원본과 비교해 바뀐 줄이 승인 목록과 정확히 같은지 확인한다.

**4단계 — 대장 대조**
1. `python3 scripts/consistency_check.py`를 실행한다. 결과는 `outputs/m{n}/consistency_report.md`에 쓴다.
2. 새 문서나 새 대장 항목이면 스크립트의 `DOCS`·`SINGLE`·`LINE_RULES`에 추가해야 대조된다. 추가했으면 보고에 적는다. 보고서 머리의 "기준" 문구도 이번 변경에 맞춘다.
3. 고친 뒤 불일치가 0건이어야 끝난다. 0건이 아니면 원인을 보고하고 다시 승인을 받는다.
4. 대조에서 뺀 위치(회의 당시 기록 절, 신구대비표 현행 칸 등)는 사유와 함께 보고서에 남긴다.

## 4. 확인 체크
- [ ] 영향 목록을 승인받기 전에 대장이나 문서를 고치지 않았다.
- [ ] 바뀐 줄이 승인한 위치와 1:1로 같다(diff 확인). 승인하지 않은 곳은 그대로다.
- [ ] `ledger.csv`의 출처·비고 칸에 변경 사유와 근거 문서가 있다.
- [ ] 날짜를 바꾼 곳의 요일이 2026년 달력과 맞는다.
- [ ] `consistency_report.md`의 고친 뒤 불일치가 0건이고, 대조에서 뺀 위치에 사유가 있다.

## 5. 하지 않는 것
- `inputs/` 원본 파일을 고치거나 지우지 않는다.
- 승인받지 않은 위치나 지정하지 않은 문장을 고치지 않는다. 어색한 표현을 다듬지도 않는다.
- 회의록의 회의 당시 기록(지정한 절 밖)을 새 값으로 바꾸지 않는다.
- 대장에 없는 항목을 임의로 만들지 않는다. `{확인 필요}`로 두고 묻는다.
- 대외 발송·게시를 하지 않는다. 초안까지만 만든다.

## 6. 출력
| 단계 | 출력 |
|---|---|
| 영향 목록 | `outputs/m{n}/impact_list.md` (승인 전 멈춤) |
| 반영 | `ledger/ledger.csv` 갱신, `outputs/m{n}/doc_{원본 ID}.md`, 회의록 지정 절 |
| 대조 | `outputs/m{n}/consistency_report.md` (고친 뒤 불일치 0건) |
| 요약 | 고친 위치 수, 대조 결과, 남은 `{확인 필요}` 목록 |

## 7. 예시
- 입력: "inputs/m4/G-M4-03_정정메모.md 반영해 줘" (FAQ 개정본 게시일 11. 11. → 11. 13.)
- 결과: 대장에 FAQ 게시일 항목이 없다는 점을 먼저 알리고, 새 항목 후보와 영향 목록을 만들어 승인을 기다린다. 승인 뒤 해당 위치만 고치고 정합 검사 결과 0건을 보고한다.
